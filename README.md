# 부산3지점 통합 영업 대시보드 — 자료 분석 → 1P 홍보물 · 학술교육 · 제안서 자동생성

PDF · PPTX 자료를 첨부하면 **A4 1페이지 홍보물**, **학술교육용 영업화법예시(5단계 교육 화법지)**, **영업 제안서 초안**을 자동으로 만들어 주는 정적 웹 앱입니다.
파일 처리는 **전부 브라우저 안에서** 이루어지며 서버 업로드가 없습니다.

- 참고한 기존 대시보드: `https://poker3120-cmd.github.io/busan-clinic-alert/` (구조·브랜드 톤 계승, 새로 구현)
- 진입 경로: `index.html`

## 0. 화면 구성 (헤더 · 메뉴)

### 헤더 — CI 마크 강조
- 씨젠의료재단 CI는 **투명 배경(차콜 워드마크 + 레드 심볼)** 자산입니다.
  어두운 빨강 밴드 위에 얹으면 흰 판(plate)을 깔아야 해서 이질감이 생기므로,
  **헤더 배경을 흰색으로 바꾸고 CI를 판 없이 그대로 노출**했습니다.
- 구성: `CI 마크 → 세로 구분선 → 대시보드 제목(레드 계열) / 부제`
- 헤더 하단에는 레드 계열 그라데이션 **액센트 라인(3px)** 을 두어 아래 메뉴 바와 색을 이어 줍니다.
- 우측 정보 칩(`영업관리 · 계획`, `김해 · 부산 서부권`)은 흰 배경 + 레드 테두리로 톤을 통일했습니다.

### 홈 — 브랜드 히어로
- 홈 최상단에 CI 마크를 크게 배치한 **브랜드 히어로 카드**를 두어, 헤더·본문·메뉴가 같은 브랜드 기준점을 공유합니다.
  - CI 마크 + `SEEGENE MEDICAL FOUNDATION` 킥커 + `부산3지점 · 영업 지원`
  - 한 줄 설명(3종 산출물 · 브라우저 내 처리)
  - `STEP 1~4` 흐름 칩 4개 (자료 → 홍보물 → 화법지 → 제안서)
- 그 아래 `작업 현황`(통계 4개) → `시작하기`(STEP 1~4 카드) → `사용 안내` 스트립 순서.

### 메뉴 — 단계형 그룹 내비게이션
업무 순서(자료 → 산출물)를 그대로 드러내도록 3개 그룹으로 묶었습니다.

| 그룹 | 항목 |
|---|---|
| (단독) | **홈** |
| `STEP 1 · 자료` | 자료 첨부·분석 |
| `STEP 2 · 산출물` | ① 1P 홍보물 · ② 학술교육 · ③ 제안서 작성 |
| (우측) | 사용 안내 |

- 내비게이션 바는 **레드 그라데이션 배경 + 흰색 버튼**, 활성 항목은 **흰 배경 + 레드 텍스트**로 반전됩니다.
- `STEP 2` 항목에는 ①②③ 번호 배지를 붙여 산출물 3종임을 표시합니다.
- `사용 안내`는 보조 메뉴이므로 테두리만 있는 ghost 버튼으로 분리하고 우측에 붙입니다.
- 모바일(≤760px)에서는 그룹 라벨·구분선을 숨기고 버튼을 세로 스택으로 정리합니다.

## 1. 주요 기능

### ① 자료 첨부 · 분석 (`자료 첨부·분석` 탭)
- PDF · PPTX **드래그 앤 드롭** 또는 파일 선택 (여러 개, 파일당 50MB 권장)
- **PDF**: PDF.js로 페이지별 텍스트 추출 + 좌표(기하) 기반 문장 복원 + 글자 크기 기반 제목 판단 + 내장 이미지 추출
  - PDF.js가 단어를 조각으로 내보내므로 **위치 좌표로 띄어쓰기·구분자를 복원**합니다 (`joinPdfParts`)
  - 아이콘 폰트의 사설 영역 문자(U+E000~U+F8FF)는 불릿(•)으로 변환 (`polishText`)
- **표 자동 인식**: 헤더 줄을 찾고 좌표로 열(column)을 추정해 `검사 코드 / 검사명 / 검체 / 검사 방법 / 검사 일정 / 보험 정보 / 검사 수가` 등을 복원합니다 (`detectTable`)
  - 표 아래의 참고문헌·각주 구간을 경계로 잘라 표 영역이 넘치지 않게 처리
- **PPTX**: ZIP 구조를 직접 해석해 슬라이드 XML 텍스트 + 발표자 노트 + `ppt/media` 이미지 추출 (외부 라이브러리 없이 동작)
- **자동 정리 항목**
  - 추정 제목 / 부제
  - 핵심 문장 후보 6개 (출처 표시)
  - 확인된 수치·근거 (민감도·특이도·정확도·AUC·일치율·수가·본인부담·검사코드 등)
  - 검사 정보 표 (`검체 / 검사 방법 / 검사 일정 / 소요 시간 / 검사 코드 / 수가·급여 / 결과 보고 / 의뢰 방법 / 보관·유의`)
  - 적용 대상 후보
- **머리글·꼬리글 자동 제거**, 페이지 번호·중복 문장 제거
- 표에 이미 쓰인 항목(검사 코드·수가 등)은 수치 카드에서 제외해 중복을 막음
- 같은 페이지의 다른 연구 결과 수치가 한 카드에 섞이지 않도록 **문장 단위로 그룹화**해 추출
- 전체 페이지를 이미지로 그린 렌더본은 ‘원본 복제’가 되므로 홍보물 이미지로 자동 선택하지 않음 (`fullPage` 표시)
- 추출 원문을 **직접 수정 → ‘내용 다시 분석’** 으로 재분석 가능
- `샘플 자료로 먼저 확인` 버튼으로 파일 없이 결과물을 미리 볼 수 있음

### ② 1P 홍보물 (`1P 홍보물` 탭)
- A4(210×297mm) 고정 캔버스, 화면 미리보기 = 인쇄 비율
- 좌측 편집기에서 문구·지표·포인트·검사 정보 표·적용 대상·이미지·연락처 수정 (입력 즉시 반영)
- **자동 맞춤**: 내용이 A4를 넘으면 4단계로 자동 축소, 1장에 맞춤
- **내보내기**
  - `PDF 저장 / 인쇄` — 브라우저 인쇄 창(‘PDF로 저장’). 텍스트가 살아 있는 벡터 PDF
  - `PPTX 저장` — PPTXGenJS로 A4 세로 1슬라이드 생성 (편집 가능한 도형·텍스트)
  - `PNG 저장` — html2canvas 2배 해상도 이미지
  - `이미지 PDF` — jsPDF로 이미지 기반 PDF
  - `내용 복사` — 메신저·메일 붙여넣기용 텍스트

### ③ 학술교육 (`학술교육` 탭)
교육자료를 한 곳에 모으고, 원장님 상담 교육용 화법지를 5단계 시간 흐름으로 만들어 **이미지로 추출**합니다.
두 개의 하위 메뉴(서브탭)로 구성됩니다.

**교육자료실 (`교육자료실` 서브탭)**
- 첨부 자료에서 만든 산출물 카드를 한 화면에 모아 봅니다
  - 1P 홍보물 (`state.flyer`)
  - 영업화법예시 (`state.training`)
- 카드마다 **바로 저장** 버튼 : `이미지(PNG)` · `이미지 PDF` · `PPTX`(홍보물만)
- 아직 만들지 않은 산출물은 회색 빈 카드로 표시하고 `만들기 →` 로 해당 화면을 엽니다
- `영업화법예시 만들기 →` 버튼으로 분석 결과에서 화법지를 즉시 생성

**영업화법예시 (`영업화법예시 (5분 화법)` 서브탭)**
- 참고 디자인(‘SALES SCRIPT · 병원 원장님 1:1 · 5분 완결’) 스타일의 **A4 1장 교육용 화법지**
- 시간대(0:00~5:00)별 **5단계** 구조
  1. `0:00-0:30` 오프닝 — 부담 없다는 신호부터 (인용 멘트 2개)
  2. `0:30-1:30` 문제 제기 — 원장님이 먼저 말하게 (질문 3개)
  3. `1:30-3:30` 핵심 가치 — 세 가지로만 정리 (핵심 가치 카드 3 · **EVIDENCE 수치 묶음** · 화법 멘트 2 · 검사 정보 표)
  4. `3:30-4:30` 반론 대응 — 한 줄로 받아치기 (반론·대응 3~4쌍)
  5. `4:30-5:00` 클로징 — 다음 약속 남기기 (화법 + 하단 강조 태그)
- **화면 구성 요소**: 상단 배지 · 제목 · 헤더 메타(검체·검사코드·수가·일정) / 5열 타임라인 바 / 단계별 번호 원형 + 시간 칩 / **짙은 남색 EVIDENCE 밴드**(자료 수록 수치 그대로) / 테두리 있는 검사 정보 표 / 반론·대응 행 / 점선 태그 / 하단 사용 기준 문구
- **수치 그룹화**: 같은 문장(=같은 연구)에서 나온 값만 한 묶음으로 정리해 서로 다른 연구 수치가 섞이지 않습니다 (`groupMetrics`)
- 좌측 편집기에서 모든 문구 수정 (인용 4 · 질문 5 · 가치 카드 4 · 수치 묶음 4 · 화법 4 · 표 8 · 반론 5 · 태그 4)
- **자동 맞춤**: 6단계 축소(`dense-1`~`dense-5`)로 A4 한 장에 맞춤
- **내보내기**: `이미지(PNG)로 추출` · `이미지 PDF` · `PDF 저장 / 인쇄` · `내용 복사`
- 홍보물과 **같은 분석 결과**를 쓰므로 자료를 한 번만 읽으면 두 산출물이 함께 나옵니다

### ④ 제안서 (`제안서 작성` 탭)
- 거래처명·담당자·제안 유형(신규 개원/거래처 전환/지원/기존 관리)·작성일
- 거래처 현황, 중점 제안, 후속 일정
- 승인 단가 · 할인율 입력 → **할인 금액·제안 단가 자동 계산**
- **A4 7페이지 문서로 조립** (`js/proposal.js`) — 표지 → 제안 요약 → 확인된 근거 → 검사 정보 → 제안 단가 → 도입 계획 → 참고 자료
- **이미지 · 그래픽 포함**
  - 표지: CI 마크 + 레드 그라데이션 액센트 바 + 지표 스탯 카드 3개
  - 근거 페이지: **지표 게이지 그래픽**(민감도·특이도·AUC를 막대로 시각화)
  - 단가 페이지: **기준가 vs 제안가 비교 막대 그래프**
  - 첨부 자료에서 추출한 이미지를 표지 이후 페이지에 삽입 (`첨부 자료 이미지를 제안서에 포함` 체크)
  - 진행 순서 타임라인·번호 배지·칩 등 벡터 그래픽
- **PDF 저장 (A4 · 다페이지)** — 페이지마다 html2canvas로 캡처해 jsPDF 7페이지로 저장. 화면 미리보기 그대로 나옵니다.
- `제안서 요약(복사·Word)에 1P 홍보물 핵심 요약을 포함` 선택 가능
- **PDF 저장 / 인쇄 / Word(.doc) 저장 / 내용 복사**

### ⑤ 사용 안내 (`사용 안내` 탭)
작업 순서, 파일 처리·저장 방식, 실제 사용 전 반드시 확인할 사항

## 2. 파일 구조

```
index.html            단일 페이지 (6개 탭 · STEP 그룹 메뉴 · 홈 브랜드 히어로)
css/style.css         공통 UI + 헤더(.brand-*) · 그룹 메뉴(.nav-group/.nav-num) · 홈 히어로(.brand-hero)
                      + A4 홍보물(.flyer) · 학술교육(.trainingsheet) · 제안서(.proposal-page/.pd-*)
                      + 서브탭(.subnav/.subtab) · 교육자료 카드(.doc-*) + 인쇄 스타일(@media print)
js/main.js            앱 진입점, 탭/서브탭 전환, 이벤트 배선, 제안서 조립·미리보기, 교육화법 배선
js/extract.js         PDF/PPTX 읽기 (텍스트·이미지 추출, 좌표 기반 표 인식, 반복 줄 제거)
js/analyze.js         분석 엔진 (제목 추정, 핵심문장 선별, 수치·검사정보·대상 추출)
js/flyer.js           홍보물 정규화 · HTML 렌더 · 편집기 UI · 자동 맞춤 측정(범용 findBestFit 포함)
js/training.js        학술교육 영업화법예시 (5단계 교육 화법지 조립·렌더·편집기·텍스트, 수치 그룹화)
js/proposal.js        제안서 A4 7페이지 렌더러 (표지·게이지·비교막대·이미지·타임라인·텍스트 요약)
js/export.js          인쇄 / PNG / 이미지 PDF / 다페이지 PDF / PPTX / Word 내보내기
js/state.js           앱 상태 + localStorage 저장
js/utils.js           공통 유틸 (escape, 다운로드, 스크립트 로더 등)
js/demo.js            샘플 자료 (파일 없이 기능 확인용)
images/ci-seegene.png 재단 CI 로고 (투명 배경 · 헤더/히어로/제안서 표지에 판 없이 직접 사용)
images/header-bg.svg  헤더 우측 장식 배경
vendor/               pdf.min.js, pdf.worker.min.js, pptxgen.bundle.js,
                      html2canvas.min.js, jspdf.umd.min.js
.nojekyll             GitHub Pages 용 (Jekyll 처리 비활성화)
```

> **참고** — PDF.js 파일은 원래 `.mjs` 확장자였으나, GitHub Pages가 `.mjs`를
> JavaScript MIME 타입으로 제공하지 않는 경우가 있어 **`.js`로 변경**했습니다.
> (`js/extract.js`의 동적 import·worker 경로도 함께 수정)

## 3. 데이터 저장 방식

| 항목 | 저장 위치 | 비고 |
|---|---|---|
| 첨부 파일 원본 | 저장 안 함 | 읽고 나면 메모리에서 해제 |
| 추출 텍스트·분석 결과 | `localStorage` (`busan3_analysis_v1`) | 원문 40만 자까지 |
| 홍보물 내용 | `localStorage` (`busan3_flyer_v1`) | |
| 학술교육 영업화법예시 | `localStorage` (`busan3_training_v1`) | |
| 제안서 초안 | `localStorage` (`busan3_proposal_v1`) | |
| 제안서 입력 폼 | `localStorage` (`busan3_proposal_form_v1`) | |
| **추출 이미지** | **세션 전용 (저장 안 함)** | 용량 문제로 저장하지 않음 → 새로고침 시 자료 재첨부 필요 |

- 이미지는 저장되지 않으므로 재방문 시 ‘자료 첨부·분석’에서 다시 읽어야 합니다.
- 완성본은 반드시 PDF · PPTX · PNG · Word 파일로 내려받아 보관하세요.
- 데이터베이스(Table/D1)를 사용하지 않습니다. 방문자별 로컬 저장만 사용합니다.

## 4. 검증 완료 사항

- 콘솔 에러 없음 (모듈 로딩·초기화 정상)
- 헤더: 흰 배경 위에 CI 마크가 **판 없이 직접** 표시되어 통일감 있게 보임 (데스크톱·모바일 확인)

## 5. 남은 작업 / 개선 아이디어

- **1P 홍보물 메뉴 존치 판단 (권장: 유지)**
  겉으로는 제안서·학술교육과 모두 A4 문서라 겹쳐 보이지만, 실제 기능은 겹치지 않습니다.
  | 구분 | 1P 홍보물 | 학술교육 화법지 | 제안서 |
  |---|---|---|---|
  | 목적 | 검사 홍보·배포 | 원장 상담 교육 | 거래처 제안 |
  | 분량 | A4 1장 | A4 1장 | **A4 7장** |
  | 고유 기능 | **PPTX 편집 저장** | 5단계 화법 구조 | 표지·그래프·단가 계산 |
  | 편집 단위 | 지표·포인트·표 | 단계별 인용·질문·반론 | 폼 입력 후 자동 조립 |
  특히 **PPTX(편집 가능한 도형·텍스트) 저장은 1P 홍보물에만** 있습니다. 삭제하면 이 기능이 사라집니다.
  대신 체감 중복은 아래처럼 줄일 수 있습니다.
  - (권장) 메뉴는 그대로 두고, 홈의 `시작하기` 카드에 이미 있는 안내 문구로 역할 차이를 명시
  - 홍보물을 학술교육 3번째 서브탭으로 옮기는 방안은 **비권장** — 가장 자주 쓰는 산출물의 접근성이 떨어집니다
- **호스팅 배포**: 현재 로컬 파일 상태이며 아직 배포하지 않았습니다.
  - **Hosted Deploy**: `membership_required` (Plus 이상 필요) → 사용 불가
  - **GitHub Pages**: 배포 준비 완료. 아래 「7. GitHub Pages 배포」 참고
- **추출 정확도**: 좌표 기반 표 인식은 열 이름이 PDF에 텍스트로 존재할 때 가장 정확합니다. 스캔본(이미지 전용) PDF는 텍스트가 없어 원문을 직접 입력해야 합니다.
- **표 열 매핑 확장**: 현재 열 이름 사전(`TABLE_COLUMNS`)은 재단 검사 안내 양식 기준입니다. 다른 양식이 반복되면 사전을 추가하세요.
- **이미지 저장**: 현재 세션 전용. 필요 시 브라우저 저장소(IndexedDB)로 이전 검토.
- **홍보물 템플릿**: 현재 1가지 레이아웃. 디자인 변형(좌우 반전, 이미지 대형 등) 추가 가능.
- **교육화법은 초안입니다**: 인사·클로징은 화법 틀(template)이며, 효능·우위·조건은 첨부 자료에 적힌 값만 사용합니다. 상담 전 반드시 읽어보고 본인 화법으로 다듬으세요.
- **표현 주의**: 완치 · 100% · 부작용 없음 · 최고 · 유일 같은 단정 표현은 쓰지 않습니다. 진단과 치료 결정은 담당 의료진의 판단에 따릅니다.
- **PPTX 내보내기**: 홍보물만 지원합니다 (교육화법은 이미지 PNG · 이미지 PDF · PDF 인쇄 · 텍스트 복사).
- **교육자료실 자료 등록**: 현재는 이 앱에서 만든 산출물 2종(홍보물·교육화법)만 표시합니다. 원본 PPT · PDF 파일을 목록에 직접 등록하는 기능은 추가 검토 대상입니다.
- **기존 대시보드 기능 이식**: 숙성영업 관리(CRM)·개원채용정보 탭은 원본 사이트에 있으며 이 프로젝트에는 포함하지 않았습니다.
- **PPTX 내보내기**: 도형·텍스트로 생성되지만 이미지 위치·폰트는 PowerPoint에서 미세 조정이 필요할 수 있습니다.

## 7. GitHub Pages 배포

이 앱은 **빌드 과정이 없는 순수 정적 사이트**입니다. 파일을 그대로 올리면 동작합니다.

### 사전 준비 완료 사항 (이 저장소에 반영됨)
| 항목 | 처리 |
|---|---|
| `.mjs` MIME 문제 | `vendor/pdf.min.mjs` → `pdf.min.js`, `pdf.worker.min.mjs` → `pdf.worker.min.js` 로 변경 |
| `js/extract.js` 참조 | 동적 import·worker 경로를 `.js`로 수정 |
| Jekyll 처리 우회 | `.nojekyll` 파일 추가 (밑줄 시작 파일·폴더가 무시되는 문제 방지) |
| 상대 경로 | 모든 자산이 상대 경로(`js/`, `css/`, `images/`, `vendor/`) → 하위 경로 배포 OK |

### 올릴 파일 (전체)
```
index.html
.nojekyll
css/style.css
js/  (main.js, state.js, flyer.js, training.js, proposal.js,
      export.js, extract.js, analyze.js, utils.js, demo.js)
images/  (ci-seegene.png, header-bg.svg)
vendor/  (pdf.min.js, pdf.worker.min.js, pptxgen.bundle.js,
          html2canvas.min.js, jspdf.umd.min.js)
```

### 배포 절차

**1) 저장소 만들기**
- <https://github.com/new> → Repository name 예: `busan3-dashboard`
- **Public** 선택 (Private은 Pages 유료 플랜 필요) → `Create repository`

**2) 파일 올리기** — 아래 3가지 중 하나

| 방법 | 절차 |
|---|---|
| 웹 UI (가장 간단) | 저장소 → `Add file` → `Upload files` → `index.html` · `css` · `js` · `images` · `vendor` · `README.md` 폴더/파일을 **폴더째 드래그** → `Commit changes` |
| GitHub Desktop | `Add local repository` → 변경 사항 `Commit` → `Publish repository` (`Keep this code private` **해제**) |
| git 명령 | `git init` → `git add .` → `git commit -m "부산3지점 대시보드"` → `git remote add origin <저장소 URL>` → `git branch -M main` → `git push -u origin main` |

> ⚠️ **`css` · `js` · `images` · `vendor` 폴더를 반드시 함께 올려야** 합니다.
> `index.html`만 올리면 화면이 스타일 없이 나오고 기능이 동작하지 않습니다.
> 웹 UI는 폴더를 드래그하면 하위 구조가 그대로 유지됩니다.

> 💡 **`Add file` 버튼이 안 보일 때** — 위치는 저장소 **Code 탭** 파일 목록의 오른쪽 위
> (`Go to file` 옆, 초록색 `Code` 버튼 왼쪽)이며, 최근 UI에서는 `+` 아이콘만 보일 수 있습니다.
> 저장소가 **비어 있으면** 이 버튼이 없고 `Quick setup` 화면의 `uploading an existing file` 링크를 씁니다.
> 가장 확실한 방법은 주소창에 직접 입력하는 것입니다.
>
> ```
> https://github.com/<계정명>/<저장소명>/upload/main
> ```
>
> 저장소 페이지 파일 목록에 폴더를 **끌어다 놓아도** 업로드 화면으로 넘어갑니다.
> 모바일 웹에서는 버튼이 숨겨질 수 있으니 PC 브라우저를 사용하세요.

> 🔁 **이미 쓰던 저장소에 올리는 경우** — 기존에 참고한 사이트처럼 GitHub Pages 저장소가
> 이미 있다면 새로 만들지 않고 그 저장소에 올릴 수도 있습니다.
> 예: `https://github.com/<계정명>/busan-clinic-alert/upload/main`
> 이 경우 기존 `index.html`이 **덮어써집니다**(이전 버전은 커밋 기록에 남아 복구 가능).
> 기존 사이트를 유지해야 한다면 **새 저장소**를 만드는 편이 안전합니다.

**3) `.nojekyll` 만들기 (숨김 파일이라 드래그로 누락되기 쉬움)**
- 저장소 → `Add file` → `Create new file` → 파일 이름에 `.nojekyll` 입력 → 내용은 비운 채 `Commit changes`
- 이미 올라갔다면 건너뜁니다. (이 저장소에는 `_` 로 시작하는 폴더가 없어 없어도 동작하지만, 두는 편이 안전합니다)

**4) Pages 켜기**
- 저장소 → **Settings** → 좌측 **Pages**
- **Source** = `Deploy from a branch`
- **Branch** = `main` / 폴더 = `/ (root)` → **Save**

**5) 접속** — 1~2분 뒤 아래 주소가 열립니다

```
https://<계정명>.github.io/<저장소명>/
```

예: 계정 `poker3120-cmd`, 저장소 `busan3-dashboard`
→ `https://poker3120-cmd.github.io/busan3-dashboard/`

> 모든 자산이 **상대 경로**라서 `https://계정.github.io/저장소명/` 같은 **하위 경로 배포에서도 그대로 동작**합니다.
> (저장소 이름이 바뀌어도 코드 수정이 필요 없습니다)
